# 0 · 2026-11-14 · 设计稿和四轮评审

## 目的

做一个开源的 macOS 写作工具（改错、润色、翻译、换语气），在任何 App 里都能用，文字可以完全留在自己的电脑上。先把设计想清楚、让「用户」挑过毛病，再写代码。

## 方法

1. **可行性调查**：在这台 Mac 上实测 Word 的脚本接口、本地模型、系统翻译。写成 `INVESTIGATION.md`。
2. **写设计稿** `DESIGN.md`，每个没实测过的技术点都标「未验证」，并写明在哪个阶段验证、不成立怎么退。
3. **三轮设计评审**：5 位模拟用户（写论文的博士后、不懂技术的 Grammarly 用户、重视隐私的工程师、记者兼译者、依赖 VoiceOver 的 macOS 工程师）。每人先写下自己一天里会做的任务，再按设计稿一步步「走」一遍，设计稿没写到的地方就是问题。每轮评完改一版，并逐条回应（`review/round-N-fixes.md`）。
4. **第 4 轮：评模型的真实输出**。六种语言 41 条语料，两个本地模型（gemma-4），6 位模拟的母语编辑逐条判「可直接用 / 小问题 / 不能用」。

## 结果

- 设计稿从 v1 到 v6。评分：第 1 轮 3–5 分，第 3 轮 6.5–8 分；问题数 97 → 86 → 37。
- 评审改掉的最重要的几件事：键盘模型（面板不激活 App 但拿键盘）、范围切成 0.1 / 0.2 / 1.0、按键含义固定（⌘⏎ 放回、⏎ 是最稳妥的动作、拿不准就复制）、Word 里的安全规则、第一个里程碑只验证不做功能。
- 模型：gemma-4-e4b 每条 12.5 秒、会改坏句子；gemma-4-12b 每条 22 秒、41 条里 14 条是空输出。**结论是没有一个本地模型可以推荐。**

## 踩坑

| 坑 | 说明 |
|---|---|
| 模型自己决定要不要「思考」 | 短句 0.8 秒，带引用和数字的句子 12 秒以上；试过的参数都关不掉 gemma-4 的思考 |
| 思考吃掉输出额度 | `max_tokens` 1024 时，正文一个字没出就结束了 |
| 防注入的分隔标记让模型思考更久 | 去掉了，只在提示词里写一句声明 |
| 17 GB 的模型在 24 GB 的机器上 | 能加载，12 分钟没有输出 |
| 模型用「删掉」代替「改正」 | 按改动比例的检查放行了它；后来改成「词保留检查」 |
| 把「license」理解成开源许可 | 用户说的是苹果开发者签名 |
| 用错了 git 身份 | 这个仓库只用 ATLAI 的身份提交和推送 |

## 经验

1. 先让模拟用户「用」设计稿再写代码，值得：键盘模型、Word 改坏引用这些问题，写完再发现要返工到窗口层。
2. 评审要有分工不同的人。不懂技术的那位最早指出「自己装 LM Studio 这一步我会放弃」。
3. 每轮逐条回应，下一轮评审会回去核对。
4. 评真实输出比评设计有用得多。
5. 速度要用真实的输入测，不能用一句短话。
