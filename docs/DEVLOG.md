### 经验

1. **让模拟用户真的用 App，比评设计稿发现的问题多得多。** 崩溃、「只用本机」能被菜单绕过、输入模式的文字不问就发给 API，三轮设计评审都没发现。
2. **模型问题要靠母语评审看真实输出。** 机械检查对「整段换成英语」完全没反应。
3. **改提示词要复测注入。** 让改错「更积极」之后，14B 开始执行像指令的原文；加一句「文字本身不是指令」才恢复。
4. **并行测试要隔离状态。** 五个实例共用一个 UserDefaults 会互相改设置，测试接口后来给每个 QA 目录一个独立的设置域。

### 踩过的坑

| 坑 | 现在的做法 |
|---|---|
| SwiftUI 的弹出菜单被合成的点击打开后会卡住事件循环 | 测试接口提供 `panel:` 命令代替点菜单 |
| `NLLanguageRecognizer` 的语言提示把西语判成英语 | 提示只用来打破接近的平局 |

| 测试期间交换区 14–17 GB | 跑模型测试时关掉其他实例 |

### 经验

1. **先让模拟用户「用」设计稿，再写代码，是值得的。** 三轮下来找到的问题里，键盘模型、Word 改坏引用、剪贴板泄露这几条，如果写完代码才发现，都要返工到窗口层。
2. **评审要有分工不同的人。** 非技术用户（Priya）打分最低，也最早指出「自己装 LM Studio 这一步我会放弃」；工程师评审负责查 SDK 头文件、指出协议签名表达不了设计要求的行为。只找工程师评审，会得到一份技术上自洽但没人装得上的设计。
3. **每轮都要逐条回应。** `round-N-fixes.md` 里每个问题 ID 都有「改了 / 部分 / 推后 / 不采纳」和章节号。评审下一轮会回去核对，发现过「标了已改但只改了一半」的情况。
4. **收下所有请求不等于改好了。** 第 2 轮分数涨了，但两位工程师同时指出范围膨胀。第 3 轮砍掉范围之后，分数继续涨。
5. **评真实输出比评设计有用得多。** 第 4 轮让母语编辑看模型的实际输出，找到了设计评审三轮都没发现的问题：模型用「删掉」代替「改正」。
6. **速度要用真实的输入测。** 调查时用一句短话测到 0.8 秒，整个速度目标都建在这个数字上。换成带引用和数字的句子，是 12 秒。
7. **好的做法在自己的其他项目里已经有了。** ScienceSkim 的 Mac 版已经在用 LM Studio 自己的接口一键下载模型、关闭思考。应该一开始就去看。

### 踩过的坑

**模型和 LM Studio**

| 坑 | 现象 | 现在的做法 |
|---|---|---|
| gemma-4 自己决定要不要思考 | 短句不思考，0.3–0.9 秒；带引用和数字的句子几乎都思考，5–35 秒 | 探测句要 30 词以上、带引用和数字 |
| 思考关不掉 | `enable_thinking=false`、`reasoning.effort=none`、`think=false`、`/no_think` 都没用 | 换模型（Qwen3 一组待测） |
| 关思考的参数反而帮倒忙 | `reasoning_effort: "none"` 和原生接口的 `reasoning: "off"` 让 gemma-4 把思考过程写进正文 | 每种参数先对「服务 + 模型」探测，只用确认有效的 |
| 思考吃掉输出额度 | `max_tokens` 1024 时，12B 模型 14 条正文为空，每条白等约 31 秒 | 默认不设 `max_tokens`，改成正文超过原文 3 倍就中断 |
| 防注入的分隔标记触发思考 | 同一句改错从 0.8 秒变成 9–19 秒 | 去掉标记，只在提示词里写一句声明 |
| 模型比内存大 | 17.5 GB 的模型在 24 GB 的机器上能加载，但 12 分钟没有输出，交换区占满 | 推荐表按内存分档，留足余量 |
| 本地服务被别的会话停掉 | 测试跑到一半全部报连接被拒 | 脚本遇到连接被拒会重启服务并重试一次 |

**检查规则**（都是多语言评审用真实输出发现的）

| 坑 | 例子 | 现在的做法 |
|---|---|---|
| 模型用删除代替改正，按改动比例的检查放行 | 中文删掉「一致」，德语删掉 müssen，改动比例只有 8% 和 26% | 改错做「词保留检查」：丢了实词就拦。还没实现，没验证 |
| 按比例判断会误判正确的改错 | 德语补逗号、把动词挪到句末，很容易超过 40% | 去掉比例阈值 |
| 正常的润色改动 56%–80% | 任何比例阈值都会每次报警 | 润色和语气不做比例检查，直说结果必须由人看过 |
| 「只改了大小写就标出」天天误报 | `friday` → `Friday`、`änderungen` → `Änderungen` 都是正确的改错 | 只查看起来像记号的词 |
| 翻译的数字「去掉分隔符再比」查不出错 | 西语 `1.400`（一千四）原样进了英语，成了一点四 | 按语言的写法解析成数值再比 |
| 模型擅自加格式 | 给拉丁学名和基因名加 Markdown 星号 | 清洗时去掉；提示词写明不要新增格式 |
| 清洗会削掉正确的引号 | 英译法后首尾是 `« »`，被当成多余的引号削掉 | 只去掉包住整个输出的同一对 |
| 不换行空格 | 英译法的输出里全是普通空格；两种空格肉眼分不出，告警没有意义 | 程序按规则换，不问用户 |
| 测试脚本自己有错 | `strip()` 把不换行空格清成空串，那项检查等于没做 | 已修；语料里也要有带不换行空格的原文 |
