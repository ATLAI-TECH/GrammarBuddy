# 7 · 2026-11-19 · 键盘操作、按 App 停用、Zotero 的 Field、首次部署、翻译方向、采用精确度

## 目的

用户这一天提的事：

1. 调查三件事：第一次用 AI 时本地部署方便不；翻译方向能不能自动判断（中 → 英还是英 → 中）；替换 / 插入 / 改词准不准。
2. 全屏状态下建议框到处跑。
3. 用键盘选中文字不出按钮；希望能用键盘操作（回车采用），Esc 一定要让框消失。
4. Word 里替换报错 `-1700 Can’t make missing value into type boolean`（截图）。
5. Word 里插入 Zotero 引用后，被当成单词 `Field`。
6. 能按 App 停用，之后还能再打开。

## 方法和结果

### 采用精确度（做了一部分）

- 新脚本 `qa/accepttest/accept_exact.py`：每采用一条，先算出「只改这一处」应得的全文，采用后把宿主的文字读回来逐字比对。测试文字 `qa/accepttest/tricky.txt` 专门放难的情况：同一句里重复的错词、要插入的句号、要删掉的重复词、emoji 前后、缩进、中文、文档最后一个字。测试接口的 `state.json` 新增 `liveMarksDetail`（每条标记的精确位置）。
- TextEdit：25 条全部逐字一致，0 条错位。
- Word：前 9 条里 8 条一致，1 条读回时中间多了一个换行，原因没查清；之后的数据被下面的事故污染，作废。Word 自己最后的文字没有多余换行。
- Safari 富文本框、Chrome：没跑。

### 事故：测试改了用户正在输入的文字

- 跑 Word 测试时用户切到 TermBuddy 打字。测试实例的实时检查跟着前台走，检查了那段中文，脚本把三条建议采用了进去（`状况 → 情况。`、插入 `时`、`n？ → 。`）。
- 原因：`guard:` 只拦点击和按键命令，没拦 `live:accept`；实时检查本身也没有限制在被测 App。
- 改：`guard:<bundle id>` 之后，测试实例的实时检查只看那个 App（别的 App 的文字不读），`live:accept/open/key/next` 也要求它在前台（除非已用 `live:app=` 钉在一个进程上）；`accept_exact.py` 自己先发 `guard:`。

### 翻译方向

- 现状：本来就是自动的，用系统的语言识别判断原文，是「我的语言」之一就译成另一种；拿不准就停下来问。
- 用 24 个难例测（`DirectionProbe.swift`）：带英文术语的中文句子被认成丹麦语或英语，`好的` 被认成繁体，`OK` 被认成波兰语，短的都「拿不准」。
- 改：先看文字系统，不用模型。汉字数 ÷ 1.7 大于拉丁字母词数、且没有假名和谚文 → 中文（6 个汉字以内分不出简繁，用用户自己的中文）。只有一两个拉丁字母词、而用户只有一种拉丁字母语言 → 就是那种，不再问。
- 结果：有明确答案的 20 个难例全部判对且不再询问。繁体 → 简体的原规则保留（有测试覆盖，用户可以用「以后都译成…」改）。

### 首次部署

- 现状：没有模型时点「润色」，面板只说「改错需要一个 AI 引擎」（操作名还写错）和一个「去设置」，要再点两三次。
- 改：面板里直接给一个大按钮。本机已有模型文件 →「用内置模型（不用下载）」；没有 →「下载并使用（大小，只需一次）」，面板里显示进度，下完自动设为引擎并执行刚才的操作。下面一行小字可以去设置里选 API / LM Studio / Ollama。
- 真实下载测试（忽略 LM Studio 的副本，模拟全新的 Mac）：Qwen3 4B 2.3 GB，约 50 秒下完（这台机器的网络），有进度，下完加载验证通过；接着点一键使用，引擎存成内置 4B，润色出了 5 处修改。测试下载的文件已删除。
- 没解决：24 GB 的 Mac 默认推荐 8.3 GB 的 14B，第一次等得久；面板里没有「先用小的」的选择。访问不了 Hugging Face 的网络（没有镜像设置）会直接失败。

### 键盘

- 用键盘选中文字（⇧ + 方向键、⌘A 等）后，在选区下方出现同一组按钮，这时它接受按键：⏎ 润色、⇥ 翻译、Esc 关闭；打别的字照常替换选区，按钮消失。鼠标选出来的按钮不接受按键。只在能通过辅助功能读到选区位置的 App 里出现。
- 建议卡片：⏎ 采用、Esc 关闭恢复为一直可用（不受「全局快捷键」开关影响）。设置里的开关改名为「全局快捷键」，只管 ⌃⌘G / ⌃⌘T / ⌃⌘J。
- Esc 保证：卡片在任何状态下（正在写入、卡片暂时不在屏幕上、按住不放）按 Esc 都关闭；按键拦截没起作用时由全局监听兜底关闭；面板开着但焦点在别的 App 里时按 Esc 也关闭面板；按钮条遇到任何按键都消失。
- 验证：卡片的 ⏎ / Esc 在 TextEdit 里测过（含「写入过程中按 Esc」）。键盘选区出按钮这条没有实测（需要真实按键，当时用户在用电脑）。

### 全屏

- 没能复现（不能把用户的屏幕切进全屏测试）。
- 从代码找到一个确定的问题：画下划线的透明窗口没有 `.canJoinAllSpaces`，它建在某个桌面上，目标 App 在全屏的另一个空间时，它没法正常出现在那里。已加上。

### Word：`-1700`

- 原因：直接替换写完之后，脚本无条件执行「把修订开关恢复成原值」。这份文档里 Word 对修订开关返回的是 `missing value`，把它写回去就报 -1700。**文字其实已经替换了**，面板却显示出错。
- 改：只有脚本自己改过开关（强制修订模式）且原值确实是 true / false 时才恢复；读开关时不是明确的 true 一律当作没开。

### Word：Zotero 引用被当成 `Field`

- 原因：Word 给辅助功能的文字在每个域（引用、日期、交叉引用）前面多念一个词 `Field`。实时检查把这段文字原样发给模型，于是句子成了「…in the lab Field (Smith 2020)…」。
- 改：发给模型之前把它去掉。判断方法：这个词前后的文字在 Word 自己的正文里连在一起出现、而带着这个词的写法不出现，就是朗读加的。模型返回的修改位置再映射回去；横跨这个词的修改丢弃；卡片上显示的前后词也不带它。
- 验证：固定用例通过（去掉朗读的 `Field`，保留真正的 `Field Museum` 和 `Springfield`，修改位置映射正确）。没有在带 Zotero 引用的真实文档上测。只处理了英文界面的 `Field`（另加了一个猜测的中文界面写法 `域`，没验证）。

### 按 App 停用

- 菜单栏菜单里多一项「在 <刚才那个 App> 里停用 / 重新启用」；设置 → 通用里列出已停用的 App，每个有「重新启用」。
- 停用后：那个 App 里不画下划线，选中文字后不出按钮；菜单里那行状态会写「已在这个 App 里停用」。全局快捷键（如果开着）不受影响。
- 只构建通过，没有实测。

## 踩坑

- 测试实例跟着前台 App 走，会碰到用户正在用的东西。两次了（上次是命令打进 TermBuddy）。
- 会话中断时一条「改代码 + 构建 + 重启」的长命令只执行了一半；恢复后要先核对哪些改动已经落盘。
- `close active document` 在用户自己也开着文档时很危险，之后只按名字关。
- 判断一个提示是不是「真的失败了」要看脚本里出错的位置：这次是写完之后才出错。

## 经验

- 任何能改文字的测试，开始前先把测试实例限制在被测 App。
- 写回类脚本里，「写」之后的每一步都不能让整件事报失败；收尾动作要各自容错。
- 语言判断这类事先用确定的规则（文字系统），不要一上来就用模型。
- 首次使用的关键一步要放在用户当时所在的地方（面板），不要让人去设置里找。

## 补充：用户同意占用前台后跑完的测试（同一天晚上）

所有测试实例都先用 `guard:` 限制在被测 App。`accept_exact.py` 改成按位置采用（`live:acceptat=位置,长度`），并把「宿主不在前台所以没试」和「被拒绝」分开统计。

### 逐字核对结果

| 宿主 | 结果 |
|---|---|
| TextEdit | 25 条一致，0 错 |
| Word（纯文字） | 25 条一致，0 错；Word 自己的文字和读回的完全相同。上次多出换行的那一条没有再现 |
| Word（带引用域、脚注、表格、批注、修订） | 7 条一致，0 错；域 3 个、脚注 1 个都还在 |
| Safari 富文本框（和 Outlook 写邮件的框同一种结构） | 修复后 24 条一致，0 错，0 拒绝 |
| Chrome 文本框 | 21 条一致，0 错；剩 3 条因为 Chrome 失去前台没有试 |

### 这一轮查出并修掉的缺陷

1. **「采用成功」的误判（真实缺陷）。** 写入后的核对只看「新文字是不是在那个位置」。删除类（新文字是空的，空串永远在）和改短类（`grows → grow`，旧词以新词开头）在写入根本没发生时也判成功。在不接受直接写入的 App（WebKit 和 Chromium 的编辑器、Outlook）里，这些建议显示已采用、实际没改，也不会走「选中再粘贴」的后路。现在核对的是「新文字 + 原来紧跟其后的几个字」并且全文长度的变化正好等于差值（`WriteBack.landed`）。面板的替换走同一个函数，也一起修了。Safari 里从 19 条成功、5 条不动，变成 24 条全部成功。
2. **Word `-1700` 的真正原因。** 上面写的「修订开关返回空值」是错的。真正的原因：脚本里新加的变量叫 `tracking`，而在 `tell application "Microsoft Word"` 里它是 Word 自己的术语（字符间距），`if tracking` 变成去问 Word 这个属性，得到空值，于是在写入之后报错。给脚本加了步骤标记（错误信息里带 `(at: …)`）才定位到。变量改名为 `gbTracked`。修复后：面板显示「已替换 3 处」，修订数 0，撤销把三处原样还原。
3. **脚注编号。** 和 `Field` 同类：Word 把脚注引用念成「空格 + 数字」，模型把这个多余的数字删掉，「数字变了」的安全检查就把整句的建议全部丢弃。现在用 Word 正文里的脚注标记（U+0002）对照，把它也从发给模型的文字里去掉。带域和脚注的那一句修复后能正常给出建议并精确写入。

### 其他项的实测

- **Zotero 式的引用域**：真实 Word 文档里，模型收到的句子已经不带 `Field`（从被拦截记录里看到的原文确认）。
- **全屏**：TextEdit 进全屏后，下划线出现在全屏空间里、位置正确；真实点击打开卡片，3 秒内位置不动；真实回车采用成功。没有复现「到处跑」。修之前是否会跑没有对照测。
- **按 App 停用**：停用后状态变成「已在这个 App 里停用」、标记清空；重新启用后 16 条标记回来。
- **键盘选中**：⇧↓ 选中一行后按钮出现；Esc 消失；再选中按真实回车打开润色面板，原文没有被换行替换；Esc 关闭面板；再选中按 Tab 打开翻译面板；面板关掉后按键回到 TextEdit。「选中后直接打字替换」没能验证：当时系统输入法是中文拼音，测试打出来的字符乱了。

### 这一轮的踩坑

- AppleScript 变量名会和应用的术语撞车，而且不报语法错。脚本里的变量加前缀。
- 判断「写入成功」不能只看新文字在不在。
- 全屏测试时点第一行文字，鼠标碰到屏幕顶端把菜单栏带了出来，点开了一个菜单；之后的按键都被菜单吃掉。全屏里的测试点要离顶端远一些。
- `set:键=`（空值）不被测试接口接受，清空要用 `set:键=nil`。
- 用户同意之后仍然会随时用电脑：测试脚本必须能分辨「没试成」和「失败」。

## 补充（11-20）：Word 里「插到下方」总是失败

- 现象（用户截图）：在 Word 里翻译后点「Insert below」，提示 `Couldn't insert; you can copy the result`。
- 原因有两个，都在 `WordBridge.insertBelow` 的脚本里：
  1. 取段落结尾用的是 `end of text object of (paragraph 1 of r)`，Word 对它什么都不返回；正确的是 `end of content of text object of …`。
  2. 插入点的变量叫 `ip`，在 `tell application "Microsoft Word"` 里是 Word 的术语，报 `Can’t set IP … Access not allowed`。和 `tracking` 是同一类问题。
  这个函数把错误吞掉只返回成败，所以界面上看不到原因。
- 改：用正确的属性；脚本变量加 `gb` 前缀；按文档名定位而不是「当前文档」；多段译文逐段插入；失败时把 Word 的原话显示出来。
- 验证：新建 Word 文档，选中一段中文 → 翻译 → 回车（插到下方）：面板显示「已插入到原文下方」，译文成为紧跟原文的新段落，前后段落不动。
- 这个问题在已发布的 0.1.0 里存在，修复还没有提交和发布。
- 经验：Word 的 AppleScript 里，变量名可能和 Word 的术语撞车且不报语法错（已经两次：`tracking`、`ip`）；所有内嵌脚本的变量统一加前缀。吞掉错误的函数要把原因带出来。
