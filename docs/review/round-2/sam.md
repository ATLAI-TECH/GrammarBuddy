# Sam（macOS 工程师，VoiceOver + 全键盘用户）— 设计评审 Round 2

评的是 `DESIGN.md` v2（2026-11-14，第 1 轮评审后）、`INVESTIGATION.md`、`review/round-1-fixes.md`。

## 结论（评分 7/10；一句话：按这份设计做出来，我会不会用，为什么）

**会试用，但开着 VoiceOver 在 Slack / VS Code / Chrome 里我不敢按 ⏎ 替换。** v2 把上一轮的三个 P0 都正面处理了：面板可成为 key、有了无障碍一节、Word 不再用文档级绝对位置并且去掉了整段替换的退路。「拿不准就复制」（§2.4）这条原则让大多数没想清楚的情况都落在安全的一侧。扣分在三处：

1. v2 新加的「经辅助功能接口分片写回」（§5.3 第 3 步）和原有的「确认没变就退到粘贴」（第 6 步）叠在一起，会把整段结果粘进一个词的位置（S2-01）。这条正好落在我这种 VoiceOver 常开的人最常走的路径上。
2. 「面板让出 key，等原窗口重新成为 key」（§4.4、§5.2）在接口上没有对应的手段和可观察的信号，面板让出 key 之后它上面的按钮（Word 的「撤销本次修改」）键盘也够不着（S2-02）。
3. `Capture` / `Replacer` / `WriteResult` 的签名表达不了设计稿自己要求的一半行为（S2-05）。

另外 0.x 的范围比 v1 大了很多（S2-11）。

## 我的任务和走查过程

机器：MacBook Pro M4 Max 64 GB，macOS 26，VoiceOver 常开，「键盘导航」打开，LM Studio 已装。因为 VoiceOver 开着，Chromium / Electron 的辅助功能树对我是打开的（§5.1 自己也这么写），所以我在 Slack、VS Code、Chrome 里走的是 §5.1 第 2 步加 §5.3，不是剪贴板方式。

### 任务 1：首次安装到第一次改错（VoiceOver 开着）

1. 引导第 1 步选语言，第 2 步「试一下翻译」。§2.10 写了开着 VoiceOver 时先让我选快捷键，默认 ⌃⌘T 不压 VO 键。这一步通了，比 v1 好很多。
2. 按 ⌃⌘T。引导窗口是自己的窗口，进程内读选区。面板出现。§3 说「打开时成为 key，VoiceOver 焦点落在结果区」，§4.4 说「面板立刻显示（不成为 key）……读完后面板成为 key」。两处说法不一样，我按 §4.4 理解：先听到「正在读取」，之后焦点进面板。**没写清的是**：面板不是 key 的那段时间，「正在读取」的播报是从一个非前台、非 key 的窗口发出来的，VoiceOver 念不念我没验证（S2-10）。
3. 完成时播报「翻译完成」。可以。
4. 第 3 步授权，每秒轮询自动前进。可以。
5. 第 4 步选引擎，探测到 LM Studio。第 5 步按 ⌃⌘G 试改错，播报「改错完成，2 处修改」，↑ ↓ 听到「第 1 处，共 2 处：Their 改为 There，已采用」。这正是我上一轮要的。
6. 按 ⏎ 替换（引导窗口内，进程内写）。通了。

结论：首次流程对我走得通。唯一悬着的是 VoiceOver 会不会跟着一个「非前台 App 的 key 面板」走，这件事 §12 第 1 项没有列，M0 的完成标准里也没有，VoiceOver 走查排在 M4（S2-10）。

### 任务 2：在 TextEdit（纯文本）和备忘录（富文本）里改一段话

选中 `Fix crash when the user have no selection and press hotkey`，按 ⌃⌘G。

1. §4.4：面板显示（不成为 key）→ 等修饰键松开 → 读 → 面板成为 key。面板先出现在哪？位置规则第一条是「选区矩形下方」，但选区矩形是读完才有的。要么面板先出现在别处、读完再跳过去，要么永远用不上第一条。没写（S2-15）。
2. 读取期间我习惯性按了一下 Esc 想取消。面板还不是 key，Esc 进了 TextEdit（无害）。如果我按的是别的键，比如字母，选中的文字被替换成那个字母。原生 App 的读取只要几毫秒，窗口很小；但剪贴板方式这段时间最长 500 ms + 1.5 s（S2-04）。
3. 结果出来，⏎。§4.4：面板让出 key，等原窗口重新成为 key，写。**怎么让出、怎么等，没写**（S2-02）。假设实现成关闭面板再写：那 §4.4 最后的「结果提示」显示在哪？
4. §5.3 分片写回：从后往前，把 `AXSelectedTextRange` 设到每一小段，再设 `AXSelectedText`。TextEdit 里我相信能成。VoiceOver 开着时，原 App 里选区每变一次我可能都会听到一次选区播报，2 处改动就是好几句（没验证，S2-19）。
5. ⌘Z：§5.7 说分片写「可能是多次 ⌘Z；做不到一次撤回的 App 改用整段写或粘贴」。在备忘录里，改用整段写就丢格式——而分片写的目的就是保格式。两个目标冲突时选哪个，没写（S2-19）。
6. **没有选区时**（§2.6）：光标停在段落里按 ⌃⌘G，处理「光标所在的段落」。面板出结果，⏎。§5.3 第 1 步「写之前重新读选区，和原文不一致就不写」——这时选区是空的，读到空串，和段落原文不一致，于是**永远不写**，退成复制。§2.6 的写回按字面走不通（S2-07）。

### 任务 3：在 Slack、VS Code、Chrome 里的 Gmail 改一句话（VoiceOver 开着）

1. 读：辅助功能树是开的，§5.1 第 2 步读到 `AXSelectedText`，`AXUIElementIsAttributeSettable` 也可能返回 true（Chromium 对可编辑区域怎么答我没验证）。`editability = .editable`，§2.4 第一行：⏎ 默认**替换**。
2. ⏎。§5.3 第 3 步分片写：对最后一处改动，把 `AXSelectedTextRange` 设到那个词（Chromium 支持设选区范围，这是 VoiceOver 的基本操作），再设 `AXSelectedText`（Chromium 多半不支持，这是我的经验判断，没验证）。
3. 第 5 步校验：`AXStringForRange(loc, 新长度)` 读回来，文字没变。第 6 步：「确认没变 → 这时才允许退到粘贴」。
4. 粘贴：合成 ⌘V。**这时原 App 的选区已经不是我当初选的那句话了，而是第 3 步设进去的最后一个词**。整段结果被粘到那一个词的位置上。结果是一句话里嵌着一整句话。
5. 我听 VoiceOver 念出来才发现。⌘Z 一次能回去（粘贴是一步），但这是按设计稿字面实现必然出现的文字损坏（S2-01，P0）。
6. Gmail 是富文本。§5.4 说「浏览器里的 Google Docs、Gmail 靠剪贴板类型判断」。但我走的是辅助功能路径，没有碰剪贴板，`isRichText = nil`。Safari 的网页内容对所有人都常开辅助功能树，所以 **Safari 里的 Gmail / Google Docs 对所有用户都是这个情况**。§2.4 的表里没有「富文本未知」这一行；`richText` 表按 bundle id，Safari 整个标成富文本也不对（S2-06）。
7. 网页区域里回退到 text marker（§5.1）。`Capture.range` 是 `NSRange?`，装不下 text marker 范围；§5.3 的分片（设 `AXSelectedTextRange`）和校验（`AXStringForRange`）在只有 text marker 的元素上都没有对应物。按 §5.3 第 6 步就是「读不回来 → unverified，不再粘贴，提示用户检查」。如果那次 `AXSelectedText` 设置其实静默无效，我得到的是「无法确认，请检查」而文字没变，之后只能自己复制粘贴。Safari 里能不能替换，整个悬在这里（S2-06）。
8. 我 ⌘Tab 去看一眼别的窗口。§2.2：结果已出就保留面板，默认动作变成复制。**我怎么回到面板？** 它不在 ⌘` 循环里，GrammarBuddy 是菜单栏 App 不在 ⌘Tab 里，VoiceOver 的窗口选择器只列当前 App 的窗口。再按一次 ⌃⌘G 会怎样，设计稿没写（S2-03）。它就这么浮在所有空间和全屏 App 上面，鼠标用户点一下就行，我够不着也关不掉。

### 任务 4：在 Word 里改论文正文的一段，5 处错误

1. 第一次用：§2.8 面板先说明，我点「继续」后才触发系统弹窗。要点「继续」，面板得先是 key。但 §4.4 的流程是「读完才成为 key」，而 Word 的读要等我点「继续」。数据流里没有这条分支（S2-04）。
2. 授权后读 `content of text object of selection`，检查只读、story、未决修订。字典里都查得到。
3. ⏎ 写为修订。§5.5 第 3 步：从后往前逐处，写前读回比对，不相等就「整次中止，撤回已写的片段」。**撤回靠什么？** 只能靠 `undo times N`，而「次数和片段数是否一一对应」是 §5.5 自己标的未验证。也就是中止路径依赖一个没验证的能力；验证不过时，中止会把文档留在改了一半的状态。其实可以不依赖它：因为是从后往前写，前面片段的位置不受后面写入的影响，完全可以**先把所有片段都读回比对一遍，全部一致再开始写**（S2-08）。
4. 写完，面板「短暂显示『撤销本次修改』」。这时面板已经让出 key（要让 Word 收到……其实 Word 走 Apple Event，根本不需要面板让出 key，这一点设计稿没区分）。假设让出了：这个按钮没有快捷键，面板不是 key，我按不到。「短暂」是几秒也没写；VoiceOver 用户从听到播报到找到按钮，几秒不够（S2-02）。
5. 我没按撤销，继续在 Word 里打了一句话，然后想起来，回头点「撤销本次修改」。`undo times 5` 撤掉的是**最近 5 步**，其中包括我刚打的那句话。按钮的有效期必须以「Word 里没有发生新的编辑」为条件，没写（S2-08）。
6. 光标在 Word 里、没有选区时按 ⌃⌘G：§2.6 只说了辅助功能接口的情况，Word 走脚本，没说（S2-07）。

## 优点

1. **§2.4「拿不准就复制」**。整张默认动作表是 v2 最好的新增。上一轮我报的 S1-07、S1-10 和别人报的丢格式问题，都被同一条原则收住了，而且「⌘⏎ 才做有风险的那个动作」对键盘用户很顺。
2. **§3 无障碍一节**逐条对应了我上一轮的 7 点建议，改动列表的念法（「第 1 处，共 2 处：Their 改为 There，已采用」）写到了可以直接实现的程度。新增文字加下划线，不只靠颜色。
3. **§2.8 / §5.5 的 Word 设计**：以 `text object of selection` 为基准、写前逐片读回比对、脚注和未决修订直接不写回、去掉了整段替换的退路。字典里 `set range`、`revision` / `field` 元素、`result range` 都查得到。「第 1、3 条有一条不过就只给差异和复制」这种写法是对的。
4. **§5.3 明确写了 `kAXSelectedTextAttribute` 在头文件里标为不可写**，并把校验结果分成三种、「无法判断时不再粘贴」。这是我上一轮 S1-05 的原样采纳。
5. **§5.2 把剪贴板方式当成主路径来设计**，并且把「不知道的事」逐条列出来按不知道处理；「面板失去 key 之后不再提供粘贴」这条推理是对的。
6. **§2.3 键盘表**：Tab 还给了系统，切换用 ⌘1–⌘5，输入模式用 ⌘⏎，组字时不响应。
7. **§12 未验证清单**每项都有「何时验证」和「不成立时怎么办」，§11 的 M0 完成标准直接是窗口和键盘模型的验证。先验证地基再往上盖，顺序对。
8. **§10 固定的自签名开发证书**解决了贡献者每次重编丢辅助功能授权的问题。
