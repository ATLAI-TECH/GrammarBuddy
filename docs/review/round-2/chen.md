### 任务 5：我想提第一个 PR（给 Ollama 加原生的关闭思考）

1. clone，`scripts/dev-cert.sh` 生成固定证书，授权跨重编保留（§10）。CONTRIBUTING 在 M0。上一轮的 C1-15 解决了。`MacQAHarness`「沿用 ScienceSkim 的」，这个工具的源码在不在本仓库里没写，外部贡献者拿不到就跑不了界面测试。记在 C2-19。
2. 看 §4.3 的 `Backend` 协议：`availability()` 和 `run(_:) -> AsyncThrowingStream<EngineEvent, Error>`。加一个 `OllamaNativeBackend` 是一个文件加一处注册，这正是我要的答案。
3. 开始写实现，发现协议缺东西：
   - `EngineEvent` 只有 `loadingModel, thinking, text(String), finished`。**没有结束原因。** 输出被 `max_tokens` 截断（`finish_reason: length`）和正常结束，在这个协议里是同一个 `.finished`。截断的结果少了后半段，如果用户按了替换，原文的后半段就没了。
   - 正文里的 `<think>…</think>` 由谁处理？§6.3 把它放在 Engine 的「输出清洗」里，但流式过程中要显示「思考中」，就得在流里识别标签并发 `.thinking`，这是 Backend 的事还是 Engine 的事，没写。我的 PR 要改哪一层取决于这个。
   - 首字超时 60 秒：思考关不掉的模型，「首字」指第一个思考 token 还是第一个正文 token？后者的话长输入会超时。
4. 顺便看了另两个协议，想判断以后给 VS Code 加适配要动哪里：
   - `Replacer.apply(_ edits:, to capture:)`：`Capture` 里没有目标 App 的 pid、没有焦点元素的引用。只凭 `Capture` 的字段，Replacer 不知道往哪里写。
   - `WriteResult.notApplied(reason: String)`：§5.3 第 6 条区分「确认没变（这时才允许退到粘贴）」和「写前检查没过（不能粘贴）」。两种都是 `.notApplied`，区别藏在一个给人看的字符串里，上层没法据此决定要不要退到粘贴。
   - `canApply` 是同步函数。能不能分片写要探测对方 App（或查表），同步函数里做不了辅助功能调用。
   - `AppProfiles` 表（§4.5）有 `reader` 字段，**没有写法的字段**。但 §12 第 3 项的退路是「该 App 改走剪贴板方式，记进 AppProfiles」，§5.7 说「做不到一次撤回的 App 改用整段写或粘贴」。这两句话都需要一个按 App 指定写法的字段，表里没有。
   - 多个 Replacer 之间谁先谁后、「一处注册」注册在哪，没写。
   见 C2-05。
5. `SystemTranslationBackend` 放在「无界面」的 `GrammarBuddyKit` 里（§4.2），但 macOS 15 上 session 只能从 SwiftUI 的 `.translationTask` 拿（§7.6，「面板视图里常驻一个」）。那这个后端在 15 上要由 App 目标里的视图把 session 注入进去，Kit 自己造不出来，「后端用假 HTTP 服务测」也覆盖不到它。见 C2-16。
6. 提示词改动怎么评审：v2 有固定语料（§9），含 Markdown、commit message、注入语句，「每个推荐模型都跑」。上一轮这条解决了。语料是人工看结果还是有自动判分，没写，不影响我提 PR。
7. 估一下项目什么时候能到「我能提这个 PR」的状态：后端在 M2。M2 的内容是：两个 AI 引擎、三个操作、差异和逐处取舍、清洗、两道检查、长文本分段、完整引导、`MODELS.md`（多语言语料 × 每个推荐模型 × 三档内存）、内置模型的技术验证。这是 v1 的两三倍。见 C2-10。

## 优点（≥3，具体到设计稿的章节）

1. **§2.4「拿不准就复制」加 §5.2 把不知道的事按「不知道」处理。** 可编辑性未知、是否真有选区未知、写前没法重读，三件事各有明确的降级。这是 v2 最重要的一个决定，它让剪贴板方式从「可能出事」变成「最坏多按一次键」。
2. **§4.5 的 `AppProfiles` 是一张表、一个文件、用户可以覆盖。** 终端只读、密码管理器排除、空选区复制整行，都是「加一行」的 PR。这是我见过的这类工具里对贡献者最友好的结构。
3. **§5.3 的三态写回结果**（确认写入 / 确认没变 / 判断不了），以及「判断不了就不再粘贴，否则可能插入两次」。用 `AXStringForRange` 校验而不是重读选区，我查了头文件，这个接口是存在的。
4. **§7.3 的去向标记只说确知的事**，把 Ollama 云端模型当成已知例外写出来；§7.4 的「测试连接」区分服务没开、被系统拦截、认证失败、没有模型四种失败。
5. **§8 有了威胁模型表**，§6.2 老实写「这挡不住所有注入」，把防线放在「结果必须经用户确认」上。比假装提示词能防注入强。
6. **§12 每一项未验证的事都有验证时间和退路**；§2.3 把键盘模型称为「整个流程的地基」并放到 M0。
7. **§10 的固定自签名证书**解决了这类项目里贡献者最烦的事（每次重编丢授权）；CI 的边界（只跑 Kit 测试）写清楚了。
