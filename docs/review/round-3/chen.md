8. `run(_ request: EngineRequest)`：**`EngineRequest` 还是没有定义**（处理说明写的是「各类型的定义」，我在 §4.3 里只找到 `TargetApp`、`Edit` 和几个枚举）。写后端的人只有这一个输入，我需要知道：里面是拼好的 system 和 user 消息，还是操作加原文；`max_tokens`、要不要关思考、模型名在不在里面。

12. 第 7–11 步见 C3-08。都不挡 M0 和 M1。

结论：M0 要先定 C3-01，M1 要先定 C3-02 和 C3-03。其余的可以边做边定。

## 优点（≥3，具体到设计稿的章节）

1. **§1.3 和 §11 的范围切分**。M0 只验证不做功能，完成标准是五条可以逐个 App 打勾的事；M2 拆成 M2a 和 M2b；推到 0.2 的每一项在正文里都用 **[0.2]** 标出并留了接口（`SelectionKind`、`writer` 里的分片、`WriteResult.partial`）。这是三轮里最大的改进。
2. **§2.3 每个动作一个固定的键**。⌘⏎ 永远是放回原处，⌘C 永远是复制，⏎ 只是别名，执行后有结果条。上一轮我在 §2.4 里绕不出来的「⌘⏎ 到底是哪个」没有了。「松开按键时才执行」这个细节把聊天软件里漏一个 ⏎ 的事故堵住了。
3. **§5.2 开头那段「先说清楚代价」**。读的那一次保护不了，直接写出来，并且写进设置开关旁边和 README。恢复时 `ConcealedType` 只在原内容本来就带时才加，这个细节是对的。
4. **§5.1 的安全输入规则**现在把目的写在规则里（「这时读不到焦点元素，没法知道它是不是密码框」），所以范围自然收窄到剪贴板方式。规则带着理由，以后有人改它时知道不能改什么。
5. **§4.3 的 `NotAppliedReason`** 把「确认没变，可以换写法」做成了类型，§5.3 第 4 条又加了「粘贴前先恢复选区并确认等于原文」。上一轮藏在字符串里的安全规则现在编译器能看见。
6. **§6.2 的三道防线各管什么、§8 威胁模型的「没挡住的」一列**。把编辑器内置终端的单行命令、长度相近的恶意改写直接列为没挡住，比上一轮写得宽的防线可信。
7. **§7.3 的「我的设备」**。让用户自己声明信任哪条链路，而不是让 App 猜 Tailscale；分类按解析后的地址、每次请求前重新判断。
