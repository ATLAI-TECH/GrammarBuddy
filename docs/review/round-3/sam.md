## 结论（评分 8/10；一句话：按这份设计做出来，我会不会用，为什么）

**会用，也愿意照这份设计开工。** 上一轮我报的 19 条，我逐条回到 v3 的章节核对：14 条已解决，3 条大部分解决，1 条随功能推到 0.2，1 条部分解决，没有只在处理说明里打勾的。范围切成 0.1 / 0.2 / 1.0、M0 只验证不做功能，这两个决定是对的。

没给更高分的原因有三个，都和「M0 只验证地基」这件事本身有关：

1. §4.4 的选择逻辑和 §4.5 的时序各自成立，放在一起对不上：时序按读法分，可是读法要试过才知道（S3-01）。

无障碍在 0.1 里**有条件地走得通**：条件是 M0 第 ⑤ 条通过，并且补上 S3-02 的播报验证。纸面上还有一处会让我听不到确认提示就把确认按过去（S3-05），要在写面板之前改掉。

## 我的任务和走查过程

机器：MacBook Pro M4 Max 64 GB，macOS 26，VoiceOver 常开，「键盘导航」打开，LM Studio 已装。VoiceOver 开着时 Chromium / Electron 的辅助功能树是打开的，所以我在 Slack、Chrome、VS Code 里走辅助功能读法；同事借我的机器、关掉 VoiceOver 时，同样的 App 走剪贴板方式。

### 任务 1：作为实现者做 M0

1. §11：搭骨架、菜单栏、快捷键、面板的窗口和键盘模型，在 8 个 App 里过五条标准。清楚。
2. 我要实现「面板的键盘模型」。§4.5 给了两种开场：一种是面板立刻出现并拿键盘，另一种是先出一个不能操作的小提示、读完才出面板。用哪一种取决于读法。**读法怎么在按下快捷键的那一刻知道？** §4.4 说先试 `lastGoodReader`，没有就试辅助功能，超时或读不到再用剪贴板。第一次在某个 App 里用时没有记录，只能先按第一种开场（面板拿了键盘）去试辅助功能；试不到要合成 ⌘C，而这时键盘在面板上，⌘C 会发给我们自己。§4.5 没有这条分支（S3-01）。
3. 第 ③ 条「`orderOut` 后合成的 ⌘C / ⌘V 到了原 App」。可以测。但通过之后，「粘贴到的是不是原来那段选区」没有要求：面板拿过键盘再还回去，网页里的选区可能已经被 blur 事件清掉了。第 ① 条只说「面板成为 key 后选区还在」，没说还回去之后还在（S3-02）。
4. 第 ② 条「按 ⏎、按住 ⏎ 不放，原 App 都收不到」。§2.3 的做法是「动作在松开按键时才执行」。主力键是 ⌘⏎ 和 ⌘C，都带 ⌘。我的经验是按着 ⌘ 时 `keyUp` 不会分发到窗口（没验证）。标准里只测了不带 ⌘ 的 ⏎（S3-02）。
5. 第 ⑤ 条 VoiceOver 光标跟随。好，这是我上一轮要的。但 §3 的反馈全靠播报，粘贴之后面板已经 `orderOut`，那句「已粘贴」是从一个没有任何 key 窗口、也不在前台的 App 发出来的。念不念不在标准里（S3-02）。
6. 假设第 ① 条在 Slack 和微信里不过。§12 第 1 项：个别 App 记进 `panelCannotBeKey`，「只对它们」改为面板激活 App。**几个算个别？** 没写。而且「面板激活 App」这个模型自己有一串没验证的事：激活之后原 App 的选区还在不在、怎么把前台还回去（SDK 里是合作式激活，可以被系统拒绝）、VoiceOver 怎么跟。M0 发现了问题，手里却没有一个验证过的退路（S3-03）。
7. M0 做完，我对「面板能不能抢键盘」有了答案，对「读不读得到、写不写得进、⌘C 发不发得出、系统会不会对读剪贴板弹窗」一条答案都没有。这些在 M1，和系统翻译、对照视图、语言引导一起做（S3-03）。

### 任务 5：Safari 里的 Gmail，把一段法语译成英语

1. 辅助功能读法（Safari 的网页内容对所有人都开着）。选区是 text marker。`AXWebArea` 里且不是 textarea → 富文本，第 5 条：⏎ 是「插入到原文下方（做不到就复制）」。
2. 插入怎么做？§2.4 说「只在知道选区位置时提供」。text marker 的位置是不透明的，§5.3 第 5 步说这种选区「直接走粘贴」。那么插入要先把选区塌到末尾再粘贴，设计稿没写这个动作，按字面就是「做不到就复制」。可以接受，有退路。
3. 我只选了段落中间的一句。「原文下方」是这句话后面，还是这一段后面？前者会把段落从中间劈开。没写（S3-08）。
4. 系统翻译，1 秒出结果，「对照 / 译文」两种视图，播报「翻译完成」。⌘C 复制。走得通。
5. 第一次遇到法语 → 英语，要下语言包：另开一个普通小窗口，「这个窗口不算离开面板」。普通窗口会激活 GrammarBuddy，原 App 不再是前台。下载完我回到面板按 ⌘⏎，§4.5 粘贴前「确认原 App 仍是前台」不过，只给复制。「不算离开」在这里兑现不了，除非关窗口时把前台还给原 App（S3-08）。

## 优点

1. **§1.3 和 §11 的切分**。0.1 的清单我数了一遍，是一个人几个月做得完的量。M2 拆成 M2a / M2b，M3 开头先做六项验证再写功能，顺序都对。
2. **§2.3「每个动作一个固定的键」**。⌘⏎ 永远是放回原处、⌥⏎ 永远是插入、⌘C 永远是复制，⏎ 只是别名。对听不到底栏的人，这比 v2 的「⏎ 看情况」好得多：我不确定的时候直接按固定的那个键。
3. **§4.5「面板出现了，键盘就在面板上」**这一条规则，加上剪贴板方式读的时候不显示面板，把上一轮 S2-04 的窗口期从根上去掉了。让出键盘的步骤（`orderOut` → 等没有 key 窗口 → 50 ms → 确认前台和焦点窗口）写到了可以照着实现的程度。
4. **§5.3 的整段写**：写前比对、用 `AXStringForRange` 读回、三种结果、只有「确认没变」才允许换粘贴并且先恢复选区再确认。上一轮的 P0 是照这个顺序堵住的，分片写回推到 0.2 并且写明了它为什么危险。
5. **§5.5 的两遍写入和那张「哪一问不过就怎么办」的表**。正常情况下不会写到一半才发现错位，中止不再依赖撤销。字典里 `revision`、`reject`、`create range`、`selection type` 我都查到了。
6. **§5.2 开头那段「先说清楚代价」**和 §8 的对应条目。读的那一半保护不了就直说，`ConcealedType` 只在原内容本来带时才加。
7. **§2.8 的「撤销本次修改（⌘Z，这时键盘在面板上）」**和「只在文档没变过时可用」。写完面板不关、不用定时消失。
8. **§3 的播报优先级表**，以及「动作执行后的播报在原 App 的选区变化之后发」。
9. **§4.6 的 `panelCannotBeKey` 和 §12 每项的退路**。大多数未验证项都写了不成立时怎么办。
