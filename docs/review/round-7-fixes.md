# Round 7 处理说明（用着顺不顺：实时标记、键盘采用、段落改写、翻译并润色）

报告：`round-7/marta.md`（6.5，TextEdit）、`ines.md`（6，只看面板和卡片）、`priya.md`（5，Chrome）、`wang.md`（4，Word）、`sam.md`（4，Safari）。共 66 条。

分数低的直接原因有两个，一个是产品的，一个是测试方式的：

- **产品**：键盘采用有真问题（连按 ⏎ 第二下会漏进 App、带修饰键的 ⏎ 也被当成采用、删除类建议采用不了），引语里的原话会被改，一处修改会被拆成两条。
- **测试方式**：评审规则不许把宿主 App 切到前台，而 Word 的新文档、Safari 的输入框、Chrome 里的采用都要宿主在前台才行，所以 wang 和 sam 一条标记都没看到。真实使用时宿主就在前台；这条路我自己验证了（Word 在前台、新建文档：3.9 秒出第一批下划线，8.5 秒标完）。第 8 轮用 `qa/front.sh` 让评审轮流用前台。

✅ 已改；◐ 部分；⏸ 推后；✗ 不采纳。

## 关于「⏎ 采用」

| 评审 | 意见 |
|---|---|
| marta | 同意：卡片要先按 ⌃⌘J 或点一下才出现，不会抢走换行；但清完最后一条后多按的那一下要接住 |
| priya | 同意，前提是每次 ⏎ 都真的改了字，或者明确告诉我没改成 |
| wang | 有保留地同意；只差大小写的建议（`FLC → flc`）不该用 ⏎ 采用 |
| sam | 交互上同意，但必须先做成明确的状态机；做不稳就退到 ⌃⌘⏎ |
| ines | 不同意，应该用 ⇥：⏎ 是全系统最忙、含义随 App 变的键 |

决定：**保留 ⏎ 为默认**（用户提出的，四位有条件同意），把四位提的条件全部做掉；设置里可以把采用键换成 ⇥（那时 → 跳过，⏎ 留给 App）。
