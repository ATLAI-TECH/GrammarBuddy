**5/10。会装来试，但按现在的写法，我每天用的四个 App（VS Code、iTerm2、Obsidian、Linear）全都落在「剪贴板兜底」这条设计稿写得最薄的路径上，而且在终端里「⏎ 替换」有可能把模型输出直接粘进 shell 执行，所以我不会把它留在常驻菜单栏里。**

### 任务 1：在 VS Code 里改一段英文 PR 描述（Markdown）

文字：

```
## Summary
This PR fix the race condition in `ConnPool.acquire()` when the pool are exhausted.
See [#482](https://github.com/acme/pool/issues/482) for detail.
```

1. 选中三行，按 ⌃⌥G。
2. §4.1 第一步：读 `kAXSelectedTextAttribute`。VS Code 是 Electron，Chromium 的辅助功能树默认不建，要有辅助技术在跑、或者有人给它的 App 元素设 `AXManualAccessibility` 才会建（我没验证，凭经验）。设计稿没提这件事，所以这一步大概率失败，也拿不到选区坐标，面板出现在鼠标旁边。
3. §4.1 第二步：模拟 ⌘C。这时我的手指还按着 ⌃⌥。**合成的 ⌘C 会不会和物理按下的 ⌃⌥ 叠成 ⌃⌥⌘C，设计稿没说**（我没验证；我知道的同类工具都要显式处理这一点，要么等修饰键松开，要么用私有事件源）。如果叠了，300 ms 内剪贴板不变，直接掉进输入模式，我会以为「VS Code 不支持」。
4. 假设 ⌘C 成功，拿到文字。「是否可编辑」这一项在剪贴板路径下怎么判断？§4.1 只在辅助功能路径里写了 `AXUIElementIsAttributeSettable`。**剪贴板路径下面板显示「替换」还是「复制」，设计稿没写。**
5. 面板出现，流式显示。我的模型带思考。§6.1 说「尝试关闭思考，按探测到的服务类型分别处理」。如果关不掉，§5.2 说会去掉 `<think>…</think>`。但流式的时候呢？思考那十几秒面板显示什么，没写。另外 Ollama 的 OpenAI 兼容接口有的版本把思考放在单独的字段里，不是正文里的标签（我没验证当前版本），那清洗规则就对不上。
6. 结果出来。我担心的是内容：反引号里的 `ConnPool.acquire()`、链接、`## ` 标题会不会被「改」。§5.1 的要求只有润色那一行提到「专有名词、数字、引用标记」，改错那一行没提，Markdown、代码、URL 哪里都没提。§5.2 还说要去掉「首尾多余的引号和代码块标记」，如果我选中的内容本来就以 ``` 开头结尾，会被当成模型的毛病删掉。
7. 按 ⏎。**面板不抢焦点（§2.2），那 ⏎ 这个键是谁收到的？** 如果键盘焦点还在 VS Code，⏎ 会把我的选区替换成一个换行。如果面板其实成了 key window，那 §4.2 的模拟 ⌘V 会不会发给面板自己？设计稿两头都没说清楚。这是主流程里最关键的一步。
8. 假设 ⏎ 被面板收到。§4.2「写之前重新读一次选区」：在剪贴板路径下，这意味着再模拟一次 ⌘C、再动一次剪贴板、再等 300 ms。设计稿没说剪贴板路径下怎么做这个检查，还是跳过。
9. 粘贴，500 ms 后恢复剪贴板。VS Code 忙的时候（大文件、扩展卡住）粘贴可能晚于 500 ms，那粘进去的就是我原来的剪贴板内容。§3.3 写了写回后「校验」，但 §4.2 只给辅助功能路径写了校验方法，粘贴路径没有。
10. 没选中文字时我误按 ⌃⌥G：VS Code 里空选区按 ⌘C 会复制整行（默认设置 `editor.emptySelectionClipboard`）。所以不会进输入模式，而是对当前行做改错，按 ⏎ 会把结果粘在光标处。Obsidian 的编辑器也是这个行为（我没验证）。

结论：能不能走通取决于第 3、7 步，这两步设计稿都没写。

### 任务 2：在 iTerm2 里改 commit message 和翻译报错

场景 A：`git commit` 打开了终端里的 vim，我写了三行英文，想改错。

1. 用鼠标选中三行，⌃⌥G。iTerm2 的辅助功能支持比 Electron 好，可能能读到 `AXSelectedText`（我没验证）；读不到就 ⌘C，iTerm2 支持。
2. 终端里选中的是屏幕上的字符，带硬换行、行尾空格，vim 开了行号还会带行号。设计稿没有提到清理这些。
3. 结果出来，按 ⏎。终端里的「选区」不是可以替换的东西。`AXUIElementIsAttributeSettable` 大概会返回不可写（我没验证），那就走粘贴兜底。**粘贴的落点是光标，不是选区**：在 vim 普通模式下，粘进去的文字会被当成一串命令执行；在 shell 提示符下，多行文字里的换行在没有 bracketed paste 的环境里等于回车。
4. 也就是说，模型的输出（来源是我选中的任意文字，可能是 README、issue、网页里复制来的日志）有一条路径可以不经我逐字检查就进入 shell。我按 ⏎ 的时候以为自己在「替换一段文字」。

场景 B：选中一段英文报错，⌃⌥T 翻译。

5. 终端输出不可编辑，§2.3 说不可编辑时默认按钮是「复制」。这个场景是好的，前提是「可编辑」判断在终端里是对的（见第 3 步）。
6. 第一次用到英→中，系统弹语言包下载窗口。设计稿 §2.3 有提前说明，好。

结论：场景 B 我会用；场景 A 按现在的设计是危险的，§8 的兼容性表里连一个终端都没有。

### 任务 4：确认我的文字去了哪里

1. 面板右上角显示「本地 · 模型名」。判断依据是 §6.2「只要地址不是本机，就显示云端」。
2. 我的 Ollama 里可以拉云端托管的模型（名字带 `-cloud` 的那类，请求发给 `localhost:11434`，由 Ollama 转发到它自己的服务器；我没在这台机器上验证，凭我对 Ollama 近一年版本的了解）。如果我在模型列表里选了这样一个模型，面板照样显示「本地」。同理，我在本机跑的 LiteLLM 之类的代理也是 `localhost`。**「本地」这个标记在说一件它不知道的事。**
3. 反过来：我另一台机器上的 Ollama（`http://studio.local:11434` 或 Tailscale 地址）会被标成橙色「云端」。这对我是误报，而且设计稿没写这种地址能不能连上：非沙盒 App 也受 App Transport Security 约束，明文 HTTP 访问非本机主机名默认会被拦（我没验证设计里打算怎么配 `Info.plist`）；macOS 15 起访问局域网还会弹「本地网络」权限，§7 的权限清单里没有这一项。
4. 剪贴板：§4.1、§4.2 每次读写都要过一遍系统剪贴板。我关心三件事，设计稿都没写：
   - 保存和恢复的是不是**所有条目的所有类型**（我剪贴板里可能是一张截图，或者密码管理器放进去的带 `org.nspasteboard.ConcealedType` 标记的密码，恢复的时候标记丢了，剪贴板管理器就会把密码记下来）。
   - 通用剪贴板：我的选中文字写进系统剪贴板的那一刻，同一个 Apple 账号的 iPhone、iPad 能不能取到（我没验证 transient 标记对通用剪贴板有没有作用）。
   - 我的剪贴板管理器不认 `TransientType` 怎么办。
5. 历史记录：§7 说默认只在内存里留 20 条，§2.7 的隐私页有开关。那「打开」之后是什么？写磁盘吗，写到哪，明文吗？20 条里存的是结果，还是原文加结果？§2.7 菜单栏「最近 5 条结果」在我共享屏幕的时候一点开就全露出来了。
6. 日志：设计稿没有一个字提到日志。DEBUG 构建的自驱动工具会截图（§8），正式版的 `os_log` 里会不会打出选中的文字、请求体？我需要一句明确的「不记录正文」。
7. 钥匙串：§6.2 说 API key 存钥匙串。本地 Ollama 不需要 key，没问题。
8. Sparkle：§7 承认这是唯一的对外请求，可以关。但没说默认是自动检查还是首次询问，带不带系统信息，更新包怎么验签。

## 优点（≥3，具体到设计稿的章节）

1. **§3.2 把核心逻辑放进无界面的 `GrammarBuddyKit`，§8 后端用假 HTTP 服务测。** 这是我愿意提 PR 的前提：改输出清洗、差异算法、提示词拼装，都可以只跑 `swift test`。第三方依赖只有 Sparkle（§3.1）也让审计成本很低。
2. **§4.2 写回前重读选区、写回后再读一次确认。** 「有些 App 返回成功但不生效」这句话说明作者知道辅助功能接口的脾气。等结果时我切走了就不替换、换成复制，这个默认是对的。
3. **§7 的默认值是我会自己选的那一组**：无统计、无崩溃上报、历史只在内存、唯一的对外请求（Sparkle）明说了而且能关；§6.2 远程接口要用户自己配、首次保存要确认、面板上常驻橙色标记。标记放在每次操作都看得见的地方，比藏在设置里强。
4. **§5.2 的「改动超过 30% 就不提供替换」**。方向对：把模型当成不可信的输入来防。阈值有问题（C1-09），但这个机制本身应该保留并扩展到其他操作。
5. **§2.6 权限在第一次用到时才请求，§4.4 没有辅助功能权限也有输入模式和「服务」菜单可用。** 我可以先不授权观察它几天，这对一个要读我所有 App 选区的工具很重要。
6. **§10 把没验证的事单独列表**，并且 INVESTIGATION 老实写了「Word 之外的通用读写没有实测」。我知道哪些话可以信到什么程度。
